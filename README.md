# Paddle

A light, hackable Mac browser on Apple's WebKit, the engine Safari uses.

- **Light:** background tabs go to sleep (their web process exits) after 30 minutes idle, when more than 10 are awake, or right away under memory pressure. Tabs making sound (even if you muted them) or using the camera or mic stay awake; video playing without sound (autoplaying previews and ads) doesn't keep a tab awake. Pages can autoplay video only without sound, as in Safari: sound starts after a click or key press. Restored sessions start with only the visible tab awake. The memory button in the toolbar shows this tab · all of Paddle; click it for a per-tab list and where the rest goes (extensions, service workers, the shared GPU and Networking processes, the app itself, cached pages, and helpers such as AutoFill that macOS counts as Paddle's but WebKit doesn't list). The readout updates every 5 seconds only while Paddle is the active app and a browser window is in view, and in whole MB. Timers in hidden pages are throttled more the longer a page stays hidden.
- **Compatible:** identifies as the installed Safari version. Popups and sign-in windows open as tabs with `window.opener` intact, and closing one returns to the page that opened it. Downloads, uploads, camera/mic prompts, HTTP logins, full screen and Web Inspector (right-click > Inspect Element) work. Links to other apps (`mailto:`, `zoommtg:`) open them; when a page rather than a click starts one, Paddle asks first. A frame from another site that starts a download also asks first (once per site per session).
- **Tabs and pages:** a tab making sound shows a speaker; click it (or Tabs > Mute Tab, ⌃⌘M, or the tab's right-click menu) to mute or unmute. A muted tab stays muted while it sleeps, but not across relaunches. File > Print… (⌘P), File > Save Page As… (⌘S, a `.webarchive`) and View > View Source (⌥⌘U). View Source shows the page's current DOM, after its scripts ran, as text in a new tab; it reads the open page and doesn't download the address again.
- **Blocks ads and trackers:** EasyList and EasyPrivacy are converted into WebKit's native content blocker, so blocking costs no extension process.
- **Customizable:** everything lives in plain files in `~/Library/Application Support/Paddle/` (Paddle > Open Config Folder). Edit, then Paddle > Reload Config (⌥⌘,). Paddle > Settings… (⌘,) edits `config.json` for you (see below); ⌘W closes it, as it does the History and Bookmarks windows.

## config.json

Only include the keys you change. A new install starts with `{}`: every key at its default.

Paddle > Settings… (⌘,) writes this file and applies each change at once. The file stays the source of truth: a save changes only the keys you changed, and top-level keys you didn't touch stay byte for byte (formatting, key order and keys Paddle doesn't know). Editing one entry of an object key (`sites`, `shortcuts`, `siteUserAgents`, ...) rewrites that whole key: its other entries keep their values and order, but their spacing and the order of the fields inside them are normalized. A value set back to its default removes the key. A key edited by hand and in Settings is never silently overwritten: if the file changed at that key since Settings read it, nothing is written and Settings offers Use the File's Value or Save Mine. While Settings is open it notices hand edits and shows "config.json has edits Paddle hasn't applied" with Apply Now (the same as Reload Config); saving any change in Settings applies them too. A `config.json` that doesn't parse shows the line and column, and Settings won't save until it is fixed; a key with the wrong type can be reset to its default from there. Settings > Advanced has Edit config.json…, Reveal in Finder and Open Config Folder; lists keys Paddle ignores (typos such as `maxAwakeTab`), each with Remove; lists problems in values Paddle reads (errors and warnings by key, with Reset or Remove where that drops only the bad value); and Tidy… shows every key that only repeats its default before removing them: top-level keys, `extensions` entries that are on, `shortcuts` entries equal to the command's default (`"none"` on a command with no default shortcut counts), and fields of a `sites` entry set to Paddle's defaults. A `sites` entry stays, even as `{}`, until Remove Site. Hand edits show up while Settings is open whether the editor replaces the file or saves in place.

## Private windows

File > New Private Window (⇧⌘N). The window's address field is tinted and labelled **Private**, and its title (Window menu, Mission Control) is always "Private Window", never a page title, since other apps can read window titles.

- **Data:** all private windows share one temporary cookie and site-data store, separate from your normal one. It is thrown away when the last private window closes; the next private window starts empty.
- **Nothing saved:** no history, no favicons, not in `session.json` or `sessions/`, and closed private tabs aren't offered by Reopen Closed Tab. Downloads are saved as files as usual; Paddle keeps no download list on disk, and private downloads leave the downloads popover when the last private window closes (one still running then leaves when it ends). Other windows' memory popovers count private tabs but don't list their titles.
- **Still works:** content blocking, `user.css` and userscripts as in normal windows. Bookmarks can be added. Address-bar suggestions read your history and bookmarks but nothing typed is recorded; a private window's tabs are suggested only in that window.
- **Extensions:** off in private windows unless `extensionsInPrivate` is `true`. While off, extensions can't see private windows or tabs, have no toolbar buttons or commands there, and extension pages don't open in them. While such a window is in front, the Extensions menu's Run Action, Show Popup and commands are disabled.
- Links from other apps open in a normal window.

## Moving from another browser

File > Import from Browser… lists the Safari, Chrome (and Brave, Edge, Arc, Chromium) and Firefox profiles it finds and brings over two things, each with its own checkbox. It reads history from a copy of the database and changes nothing in the old profile, and the result sheet says what was imported and what was skipped and why. Paddle never reads Keychain, saved passwords, cookies or any other part of the profile.

- **Settings:** the default search engine, the home page and the bookmarks bar, written to `config.json` the way Settings writes it (a key you edited by hand meanwhile is not overwritten). The engine must be one Settings offers (DuckDuckGo, Google, Bing, Brave, Kagi, Ecosia); any other is reported and your engine stays. A home page comes over only where the old browser really opens one in new windows. New tabs come over only from Safari, when its new tabs open the home page.
- **History:** the newest 200,000 visits with their original dates, web pages only (`http` and `https`; internal pages, files and extension pages are skipped). Visits already in Paddle's history are skipped, so importing twice adds nothing, and visits older than `historyDays` are skipped too (they would be deleted again at once). With `historyDays` at 0 nothing is imported.
- **Where from:** Safari `~/Library/Safari/History.db` and its preferences in `~/Library/Containers/com.apple.Safari/`; Chrome and the browsers built on it, `History` and `Preferences` in each profile folder under `~/Library/Application Support/`; Firefox, `places.sqlite`, `prefs.js` and `search.json.mozlz4` in each profile listed in `profiles.ini`.
- **Other browsers' data is protected by macOS too, not only Safari's:** Chrome, Edge and Firefox keep theirs in folders macOS guards, as Safari does. Without Full Disk Access Paddle can't read them, and each shows as needing it in the list (Safari always does, since its files can't be checked without the permission). To import from one, allow Paddle in System Settings > Privacy & Security > Full Disk Access, or export bookmarks as HTML (see Bookmarks). Paddle never asks for the permission itself.
- **Bookmarks:** export them from the old browser as an HTML file, then Bookmarks > Import Bookmarks… (the import sheet has a button for it).
- **Passwords:** Paddle never reads them. Export them from the old browser or your password manager as a file, import that file into your password manager extension, then delete the file, since it holds your passwords in plain text. For Proton Pass, import in the Proton Pass extension's settings (or in its web app at pass.proton.me); see Proton Pass's import help for the formats it accepts and the exact steps. Old browsers: Chrome exports from its password manager's settings, Firefox from `about:logins`, Safari from the Passwords app's File menu.
- **Cookies and sessions:** not imported. You sign in to each site again.
- **Extensions:** not migrated. Reinstall them (see Extensions below); their storage starts empty, so sign in to each extension again too.

## Extensions

Paddle runs WebExtensions (the Chrome and Firefox add-on format) on WebKit's own extension support, the same engine Safari uses for web extensions. Manifest V3 and whatever V2 support WebKit provides.

- **Installing:** put each unpacked extension in its own folder in `extensions/` (Extensions > Open Extensions Folder): a folder with `manifest.json` at its root, or a folder holding exactly one such folder (the usual unzip layout). Zips and `.crx` files must be unzipped first; a folder without a manifest gets a status line, not a load. Paddle > Reload Config picks up added, removed, enabled and disabled folders; Extensions > Reload Extensions reloads everything, edited files included.
- **Installing from the Chrome Web Store:** Extensions > Install from Link… takes a Chrome Web Store link (`https://chromewebstore.google.com/detail/…`) or a 32-letter extension id; on a store page, a bar under the toolbar offers "Install <name> in Paddle" (or says it is installed). Paddle downloads the package from Google's update service (no cookies, 100 MB cap, redirects only to Google's download servers) and checks Google's Web Store signature and the developer's key before unpacking; it also checks the archive for unsafe names, links and anything the archive doesn't list. A package that fails any check is refused and nothing is installed. It lands in its own folder in `extensions/`, named from the extension, and is recorded in `extension-sources.json`; then the extension asks for its permissions as usual. It runs as Chrome, with its store id when it needs one (sign-in through `identity`, `oauth2`, `externally_connectable`). Installing the same extension again offers to replace it when the version differs (its settings and data stay) and says it is already installed otherwise. Updates are described under Updates.
- **Installing from Firefox Add-ons:** Extensions > Install from Link… and the bar on an addons.mozilla.org add-on page take an add-on link (`https://addons.mozilla.org/<locale>/firefox/addon/<slug>/`). Paddle looks the add-on up on addons.mozilla.org, downloads its current `.xpi` (https, redirects only to Mozilla's add-on hosts, 100 MB cap) and checks it against the file's size and SHA-256 from that lookup. Then it checks the archive as for a Chrome package and Mozilla's signature: every file's SHA-256 in `META-INF/manifest.mf`, the manifest's digest in `mozilla.sf`, and the CMS signature in `mozilla.rsa`, made by a certificate named for the add-on's id, which `manifest.json` must also name as its gecko id. That certificate must chain to Mozilla's add-on root, which Paddle bundles (`root-ca-production-amo`, the same certificate Firefox carries); if the bundled root were missing or altered, an add-on would say its chain isn't verified and ask "Install anyway?", and its record would say `"verified": false`. Installed add-ons run as Firefox and are recorded like Chrome installs.
- **Updates:** each extension installed from a store is checked once a day, at launch and hourly, while `extensionUpdates` is on in config.json. The check asks the store: Google's update check for a Chrome Web Store extension, the add-on's lookup on addons.mozilla.org. A newer version is downloaded and checked exactly as an install is, and it must be the version the store named and newer than the installed one (downgrades are refused). If it asks for nothing you haven't granted, and for an add-on Mozilla's certificate chain is verified, it replaces the installed copy quietly: same folder, settings and data, then it reloads. If it asks for more, the installed copy keeps running, the new copy waits in `extensions/.staged-<folder>/`, and the update alert names what is new. Allow swaps it in and grants those; Don't Allow discards it, and Paddle doesn't ask again for that version. An add-on whose chain isn't verified always gets the alert, as it does at install. Extensions > Check for Extension Updates checks every store install now and shows a summary. Each folder's result (up to date, updated to X, update X waiting for permission, or the reason it failed) is listed in the Extensions menu and the log. Folders you put in by hand are never updated.
- **Permissions:** before an extension first runs, Paddle lists what it wants and offers **Allow** (everything it asks for), **Only When I Click** (its APIs, but no site until you click its button, which grants that tab for that click) or **Don't Allow**. A running extension asking for more gets the same prompt; a site it is refused for isn't asked about again until relaunch, whichever page on the site it asks about. One kind of request never shows an alert: an extension asking to see tabs on sites it hasn't been granted (WebKit asks when `tabs.query` or a failed cross-origin fetch would reveal them) without being tied to a tab and without a click on its button, popup, menu item or command in the last 5 seconds (an open popup counts). Paddle says no at once, so the extension still gets those tabs without their address or title, logs a line, and the extension's Extensions menu shows "N site requests auto-denied — Review…", which lists the sites and allows the ones you tick (the site and its `www.` form). Answers are kept in `extension-permissions.json` (per folder name, hand-editable; `"click"` marks a site left to Only When I Click); delete an entry, or use the extension's "Ask About Permissions Again" (its Extensions menu, or Settings > Extensions, which also works for a declined extension that isn't running), to change them. If the file is corrupt, no extension loads until it is fixed or deleted.
- **Using them:** each extension with a toolbar action gets a button right of the address bar with its badge; click it for its popup (sign in to a password manager there) and again to close it, right-click for Options, permissions and the extension's own items. A popup opens only from a click, a menu item or a command; an extension can't pop it up on its own. The Extensions menu lists every running extension with its commands, options page, problems and, with `developerTools` on, Inspect Background Page; the load status of every folder is at the bottom. Keyboard shortcuts from an extension's manifest work in browser windows and run before the page sees the key, as in Chrome, except a key one of Paddle's menu items uses, which stays Paddle's. Extension pages open as tabs; sleeping tabs look like Chrome's discarded tabs to them. `tabs.move` with a window id and `windows.create` with tab ids move tabs between windows, page and history included; a window left with no tabs closes, as in Chrome. Failures at startup show in a banner in the window.
- **What extensions can block:** a declarativeNetRequest extension blocks with its rules, and WebKit applies them: the rule files in its manifest and the rules it adds while it runs. An extension that asks for `webRequestBlocking` without rule files doesn't block anything here, because WebKit delivers the requests to its listeners and ignores their answers: whatever it would block or change still loads. That covers uBlock Origin's MV2 build, which blocks only that way, and extensions that ask for it for other reasons, such as Proton Pass's HTTP auth handling (see Compatibility). Its permission prompt says so when you first allow it, and the log records it at each load. Its content scripts still run, so the hiding they do on a page still works. Paddle's own lists block whatever the extensions do: EasyList and EasyPrivacy, the optional uBlock Origin lists (Settings > Privacy & Blocking > Filter lists > uBlock Origin lists > Add) and `user-filters.txt`.
- **What extensions can see:** extensions are third-party code. "Allow" usually means every site, signed-in pages included, until you change it. With `tabs`, they see every tab's address and title, sleeping tabs included. They share the browsing cookie store, so `cookies` sees your site cookies. They get no history, bookmarks or downloads API. Native messaging reaches only Paddle's own compatibility channel (`com.walker.paddle.compat`, answered inside Paddle); any other app id gets Chrome's "Specified native messaging host not found.", and Paddle never launches an app for an extension. Anything that can write to Application Support can pre-approve an extension: the same trust level as `config.json`. An extension and the built-in blocker can both block, so turn one off to compare.
- **Compatibility:** Paddle runs each extension as the browser it was built for (`extensionCompat` overrides it per folder). A Firefox build (a gecko id and a background that isn't only a service worker) runs as Firefox: its pages are `moz-extension://<uuid>/`, its own views send Firefox's user agent, and `runtime.getBrowserInfo` says Firefox. Its `runtime.id` stays the private id it always had, so its storage carries over; saved tabs on its old `webkit-extension://` pages move to the new address (without their back history). Anything else that isn't a Safari build runs as Chrome: `chrome-extension://` pages under a private id in Chrome's a–p letters, Chrome's user agent and `navigator.userAgentData`, `chrome.app`, and no `browser` object. Safari builds run untouched (`native`). Both personas load from a patched clone in `extension-overlays/` (kept while the folder is unchanged; its two generated scripts are rewritten at every load): `paddle-prelude.js` runs first in the background (first in `background.scripts`, through a `paddle-sw.js` wrapper next to a service worker, or by a script tag in every page, popups, options and a background page included) and `paddle-content.js` first in each of its own isolated-world content scripts. No content script or site pattern is added. The prelude fills in what WebKit lacks: Chrome's enums and constants, inert `runtime.onUpdateAvailable` / `onSuspend` / `onRestartRequired` events, `requestUpdateCheck`, `runtime.getManifest()` as the extension wrote it, `permissions` that leave out Paddle's own grant and answer names WebKit doesn't know, `i18n.getMessage("@@ui_locale")`, `action.getUserSettings`, `tabs.getCurrent()` as undefined in the popup, an empty read-only `storage.managed`, the MV2 `extension.sendRequest` / `getURL` aliases, `runtime.onInstalled` with `install` on a folder's first run (WebKit never sends it; `extension-installs.json` remembers), and `requestIdleCallback`. If a background fails to load with the prelude, Paddle loads that extension again from its own folder for the rest of the session and its status says "compat off". User agents: popups, extension-page tabs and a background page send the persona's; a service worker's own requests still send Safari's. WebKit drops `webRequestBlocking` (listeners fire, but blocking answers are ignored), `privacy`, `webRequestAuthProvider`, `clipboardRead` and `offscreen`. For Proton Pass that means no site logos (initials instead), no HTTP basic-auth fill, no clipboard auto-clear, no unlock through the desktop app, and the "disable browser password manager" toggle does nothing; sign-in, vault, autofill, the save prompt and passkeys don't depend on those. Proton Pass's popup gets its full 600×430 layout from that `tabs.getCurrent` fix; with `"persona": "none"` it lays itself out at tab size (356×338), since that clone has no prelude in its pages. Paddle switches on WebKit's `requestIdleCallback` for every page (Proton Pass's form detector needs it). Proton's sign-in pages pick how to talk to the extension from the browser name, so give them Firefox's: `"siteUserAgents": {"account.proton.me": "Mozilla/5.0 (Macintosh; Intel Mac OS X 10.15; rv:157.0) Gecko/20100101 Firefox/157.0", "pass.proton.me": <same>}` (Settings > Sites' Firefox preset).
- **Files:** `extensions/` (the folders), `extension-permissions.json` (your answers), `extension-id-salt` (per-install ids; deleting it changes every extension's id and orphans its storage and restored extension tabs), `extension-sources.json` (which folders came from a store, with the store id, version, install date, the last store check, a hash of each file, `verified`, which is `false` for a Firefox add-on whose certificate wasn't checked, and `declinedVersion`, an update you refused; a folder's record is dropped when the folder is deleted), `extension-installs.json` (when each folder first ran, for `runtime.onInstalled`; made from the permissions file the first time, so extensions that ran before it existed don't count as new), `extension-overlays/` (the patched clones; on the same APFS volume they cost almost no disk, but a folder symlinked in from another volume is copied in full and its status line says "copied, N MB"; safe to delete, remade at the next load). Extension storage lives in `~/Library/WebKit/com.walker.Paddle/WebExtensions/`; deleting an extension's folder keeps its storage and permission entry.
- **Not supported:** native messaging to real apps, page context-menu items, private windows unless `extensionsInPrivate` (and `windows.create` never opens one), muting through the tabs API.

## Other files

- `history.sqlite`: browsing history (History > Show All History, ⌘Y; File > Import from Browser… adds another browser's). The address bar suggests open tabs, history and search phrases as you type and completes known hosts inline.
- `bookmarks.json`: bookmarks, as `{"bar": [...], "menu": [...]}` of `{"title": …, "url": …}`; folders have `children` instead of `url`. Paddle adds an `id` to each entry; hand-written entries can leave it out. Edit by hand and Reload Config (an in-app edit also picks up hand edits first), or use Bookmarks > Show Bookmarks (⌥⌘B). ⌘D or the star bookmarks the page to the bar; Edit > Undo reverses bookmark edits. Import/Export Bookmarks… read and write the HTML file Safari, Firefox and Chrome use.
- `favicons/`: site icons, one 32 px PNG per site, refetched weekly. WebKit fetches them (512 KB cap) only from hosts the page itself loaded from, otherwise `/favicon.ico`; SVG icons are skipped. Clear History removes them except for bookmarked sites, and with history off only bookmarked sites' icons are kept. Safe to delete.
- `user.css`: applied to every page.
- `user-filters.txt`: your own Adblock Plus rules (`||host^`, `site.com##.selector`). A selector WebKit cannot parse is dropped and counted as invalid in the status line, not applied in part. Exceptions here work across lists: every `@@` line (including `@@||site^$document`, which turns blocking off on that site) and every `site.com#@#.selector` line is appended to each downloaded list when it compiles, so they cancel EasyList's and EasyPrivacy's blocks and hiding too. Changing them recompiles every list at the next Reload Config; changing only other lines recompiles just this file. `contentBlocking: false` turns all blocking off.
- Filter syntax: `||host^`, `|anchor|`, `*`, `^`, options WebKit can express (`third-party`, `domain=`, resource types, `match-case`, `important`, `$document` on `@@`, with or without `||`), `##` hiding with `#@#` exceptions, and `/regex/` rules. `subdocument` / `frame`, and rules with only negated types (`$~script`), block frames but never a page you navigate to. `$important` blocks beat the list's own `@@` lines; your `@@` lines and sites with blocking off still beat them. A regex is rewritten for WebKit only when the result matches exactly the same URLs (`\d` and `\w` become classes, a `-` next to them in a class is a hyphen as in JavaScript, `{2,4}` is written out up to 32 copies, `(a|b)` becomes one rule per alternative, up to 32, each at most 200 characters); lookarounds, `\b`, backreferences, backwards ranges like `[z-a]` and anything longer are refused, counted as "regex: N translated, M refused" in the status line. If WebKit still refuses a list that has regex rules, it is compiled once more without them and the status line adds "regex rules left out: WebKit refused them (reason)". Selector lists are split, so `site.com#@#.sidebar` also excepts the `.sidebar` of `##.ad, .sidebar`. A generic `##.ad` with `site.com#@#.ad` keeps hiding everywhere but that site; a `site.com##.ad` that a `#@#` names (or names a subdomain of) is dropped for that rule. Scriptlets (`##+js`), extended selectors and options like `redirect`, `csp`, `removeparam`, `replace=`, `header=` are counted as unsupported, never approximated; the Activity popover's "Not covered" line for each list says how many of each kind.
- Startup blocking: windows and tabs open at once, but a tab's first page waits until every block list is installed, at most 3 s. Lists compile in parallel and each starts blocking as soon as it is compiled (cached lists load in milliseconds); a page that loaded during a slower compile reloads once when the lists are in, unless it came from a form post, is playing media or using the camera or microphone, or you typed into it. On a first launch (a default list's file missing from `filters/`) Paddle copies the EasyList and EasyPrivacy snapshots bundled in the app, fetched 12 Oct 2026 (`! Version: 202610121715`), so blocking starts without the network; the file is dated by that version, so the automatic update replaces it once it is `filterUpdateDays` old (with `filterUpdateDays: 0`, only Update Filter Lists does).
- `userscripts/*.js`: Greasemonkey-style scripts (`@match`, `@include`, `@exclude`, `@run-at`, `@noframes`, `@inject-into content`). A file without a header runs everywhere. `GM_*` APIs are not provided.

## Install

`scripts/release.sh` builds a Release signed with Developer ID (hardened runtime, secure timestamp), checks it with `codesign --verify --deep --strict` and refuses a build carrying `get-task-allow`. Every step prints PASS or FAIL, and a summary marks steps that didn't run as SKIP (a step that dies on an unexpected error or Ctrl-C shows as FAIL).

- no flags: build, sign, verify, and zip to `dist/Paddle-<version>-<build>-unnotarized.zip`.
- `--notarize`: also submit a scratch zip with `notarytool` (keychain profile `walker-notary`, or `NOTARY_PROFILE`), staple the app and check it with `spctl`. Only then is `dist/Paddle-<version>-<build>.zip` written, from the stapled app.
- `--install`: also quit a running Paddle, verify a staged copy, swap it into `/Applications/Paddle.app` (the old copy is restored if anything fails), and print the installed version and Gatekeeper's verdict. Without `--notarize` that line says UNNOTARIZED.

`SIGN_IDENTITY` picks a certificate by SHA-1 when more than one Developer ID matches. Once Paddle is in `/Applications`, Paddle > Make Paddle the Default Browser… asks macOS to make it the default; copies run from elsewhere (debug builds) refuse.
