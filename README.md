# Paddle

A light, hackable Mac browser on Apple's WebKit, the engine Safari uses.

- **Light:** background tabs go to sleep (their web process exits) after 30 minutes idle, when more than 10 are awake, or right away under memory pressure. Tabs making sound (even if you muted them) or using the camera or mic stay awake; video playing without sound (autoplaying previews and ads) doesn't keep a tab awake. Pages can autoplay video only without sound, as in Safari: sound starts after a click or key press. Restored sessions start with only the visible tab awake. The memory button in the toolbar shows this tab · all of Paddle; click it for a per-tab list and where the rest goes (extensions, service workers, the shared GPU and Networking processes, the app itself, cached pages).
- **Compatible:** identifies as the installed Safari version. Popups and sign-in windows open as tabs with `window.opener` intact, and closing one returns to the page that opened it. Downloads, uploads, camera/mic prompts, HTTP logins, full screen and Web Inspector (right-click > Inspect Element) work. Links to other apps (`mailto:`, `zoommtg:`) open them; when a page rather than a click starts one, Paddle asks first. A frame from another site that starts a download also asks first (once per site per session).
- **Tabs and pages:** a tab making sound shows a speaker; click it (or Tabs > Mute Tab, ⌃⌘M, or the tab's right-click menu) to mute or unmute. A muted tab stays muted while it sleeps, but not across relaunches. File > Print… (⌘P), File > Save Page As… (⌘S, a `.webarchive`) and View > View Source (⌥⌘U). View Source shows the page's current DOM, after its scripts ran, as text in a new tab; it reads the open page and doesn't download the address again.
- **Blocks ads and trackers:** EasyList and EasyPrivacy are converted into WebKit's native content blocker, so blocking costs no extension process.
- **Customizable:** everything lives in plain files in `~/Library/Application Support/Paddle/` (Paddle > Open Config Folder). Edit, then Paddle > Reload Config (⌥⌘,). Paddle > Settings… (⌘,) edits `config.json` for you (see below); ⌘W closes it, as it does the History and Bookmarks windows.

## config.json

Only include the keys you change. A new install starts with `{}`: every key at its default.

Paddle > Settings… (⌘,) writes this file and applies each change at once. The file stays the source of truth: a save changes only the keys you changed, byte for byte everywhere else (formatting, key order and keys Paddle doesn't know stay), and a value set back to its default removes the key. A key edited by hand and in Settings is never silently overwritten: if the file changed at that key since Settings read it, nothing is written and Settings offers Use the File's Value or Save Mine. While Settings is open it notices hand edits and shows "config.json has edits Paddle hasn't applied" with Apply Now (the same as Reload Config); saving any change in Settings applies them too. A `config.json` that doesn't parse shows the line and column, and Settings won't save until it is fixed; a key with the wrong type can be reset to its default from there. Edit config.json… is under Settings > Advanced.

| Key | Default | Meaning |
|---|---|---|
| `homepage` | `about:blank` | Page for a new window (`about:blank` = empty, address bar focused) |
| `newTabPage` | `about:blank` | Page for a new tab |
| `searchTemplate` | `https://duckduckgo.com/?q=%s` | Search URL, `%s` = query |
| `searchSuggestTemplate` | `https://duckduckgo.com/ac/?q=%s&type=list` | Address-bar search suggestions (OpenSearch or DuckDuckGo JSON). Only search words typed key by key are sent, never addresses, paths or pastes; `""` = off |
| `historyDays` | `365` | Days of history kept in `history.sqlite` (0 = no history) |
| `tabSleepAfterMinutes` | `30` | Idle minutes before a background tab sleeps (0 = never) |
| `maxAwakeTabs` | `10` | Most tabs awake at once (0 = no cap) |
| `sleepPinnedTabs` | `false` | Let pinned tabs sleep too |
| `contentBlocking` | `true` | Ad and tracker blocking |
| `filterLists` | EasyList, EasyPrivacy | Adblock Plus lists (https URLs) fetched by Paddle > Update Filter Lists into `filters/` (the two defaults as `easylist.txt` and `easyprivacy.txt`, any other as `<name>-<hash of its URL>.txt`, so two lists with the same file name never collide; a list downloaded before the hash existed is renamed from `<name>.txt` once when no other list could own that file). Only these lists and `user-filters.txt` block: remove a list here and it stops blocking at the next Reload Config, while its file stays in `filters/` unused. Content blocking in the Activity popover and the Reload Config alert show a line for each, e.g. `easylist: 61,234 rules (1,830 lines unsupported; 40 style rules; 3 invalid selectors; cached)`, `user-filters: 0 rules (4 comment lines)`, or why a list failed to compile. "Style rules" are `##selector {style}` and `:style(` lines, which inject CSS rather than hide and are never turned into hiding; "invalid selectors" are `##` selectors WebKit's parser refuses (nested `:has`, unbalanced brackets), dropped one by one when a list compiles so that the valid selectors sharing a rule with them keep working |
| `filterUpdateDays` | `7` | Days between automatic downloads of `filterLists`, checked at launch and hourly. Each list is judged by its own file in `filters/`: a list is fetched when its file is missing (new or never downloaded) or older than this, so a failed list is retried at the next hourly check. Failures show under Content blocking in the Activity popover. `0` = only by hand, except a list whose file is missing |
| `userAgentSuffix` | `""` | Replaces `Version/… Safari/…` (empty = match installed Safari) |
| `siteUserAgents` | `{}` | Full user agent per site, e.g. `{"example.com": "Mozilla/5.0 …"}` |
| `sites` | `{}` | Per-site settings by host suffix (`"example.com"` also covers `www.example.com`; the longest match wins each field): `{"example.com": {"zoom": 1.25, "javaScript": false, "autoplay": "allow" / "muted" / "block", "contentBlocking": false, "location": "ask" / "allow" / "deny"}}`. Every field is optional. User agents stay in `siteUserAgents` |
| `showTabMemory` | `true` | Memory readout in the toolbar |
| `developerTools` | `true` | Inspect Element in the context menu and Safari's Develop menu. Open pages keep the setting they loaded with; extension popups and pages pick up a change after a relaunch |
| `extensions` | `{}` | Turn an extension off by its folder name, e.g. `{"protonpass": false}`. Folders not listed are on |
| `extensionsInPrivate` | `false` | Run extensions in private windows too. Turning it on applies to private windows opened afterwards; turning it off (Reload Config) also takes extensions out of private windows already open, reloading their pages without them |
| `shortcuts` | `{}` | Rebind menu commands, e.g. `{"nextTab": "cmd+option+right", "closeTab": "none"}`. Write a shifted key as the key plus `shift` (`cmd+shift+[`, not `cmd+shift+{`) |

Shortcut action names: `settings`, `openConfigFolder`, `reloadConfig`, `updateFilterLists`, `makeDefaultBrowser`, `hide`, `hideOthers`, `quit`, `newTab`, `newWindow`, `newPrivateWindow`, `openLocation`, `closeTab`, `closeWindow`, `reopenClosedTab`, `savePage`, `print`, `undo`, `redo`, `cut`, `copy`, `paste`, `pasteAndMatchStyle`, `selectAll`, `find`, `findNext`, `findPrevious`, `reload`, `hardReload`, `stop`, `zoomIn`, `zoomOut`, `actualSize`, `viewSource`, `webInspector`, `fullScreen`, `back`, `forward`, `showHistory`, `clearHistory`, `addBookmark`, `showBookmarks`, `toggleBookmarksBar`, `importBookmarks`, `exportBookmarks`, `nextTab`, `previousTab`, `togglePin`, `duplicateTab`, `toggleMute`, `sleepBackgroundTabs`, `tab1` … `tab9`, `openExtensionsFolder`, `reloadExtensions`, `minimize`.

Modifiers: `cmd`, `shift`, `option`/`alt`, `ctrl`. Named keys: `left right up down tab return escape delete space home end pageup pagedown f1`–`f12`.

## Private windows

File > New Private Window (⇧⌘N). The window's address field is tinted and labelled **Private**, and its title (Window menu, Mission Control) is always "Private Window", never a page title, since other apps can read window titles.

- **Data:** all private windows share one temporary cookie and site-data store, separate from your normal one. It is thrown away when the last private window closes; the next private window starts empty.
- **Nothing saved:** no history, no favicons, not in `session.json`, and closed private tabs aren't offered by Reopen Closed Tab. Downloads are saved as files as usual; Paddle keeps no download list on disk, and private downloads leave the downloads popover when the last private window closes (one still running then leaves when it ends). Other windows' memory popovers count private tabs but don't list their titles.
- **Still works:** content blocking, `user.css` and userscripts as in normal windows. Bookmarks can be added. Address-bar suggestions read your history and bookmarks but nothing typed is recorded; a private window's tabs are suggested only in that window.
- **Extensions:** off in private windows unless `extensionsInPrivate` is `true`. While off, extensions can't see private windows or tabs, have no toolbar buttons or commands there, and extension pages don't open in them. While such a window is in front, the Extensions menu's Run Action, Show Popup and commands are disabled.
- Links from other apps open in a normal window.

## Extensions

Paddle runs WebExtensions (the Chrome and Firefox add-on format) on WebKit's own extension support, the same engine Safari uses for web extensions. Manifest V3 and whatever V2 support WebKit provides.

- **Installing:** put each unpacked extension in its own folder in `extensions/` (Extensions > Open Extensions Folder): a folder with `manifest.json` at its root, or a folder holding exactly one such folder (the usual unzip layout). Zips and `.crx` files must be unzipped first; a folder without a manifest gets a status line, not a load. Paddle > Reload Config picks up added, removed, enabled and disabled folders; Extensions > Reload Extensions reloads everything, edited files included.
- **Permissions:** before an extension first runs, Paddle lists what it wants and offers **Allow** (everything it asks for), **Only When I Click** (its APIs, but no site until you click its button, which grants that tab for that click) or **Don't Allow**. A running extension asking for more gets the same prompt; a site it is refused for isn't asked about again until relaunch, whichever page on the site it asks about. One kind of request never shows an alert: an extension asking to see tabs on sites it hasn't been granted (WebKit asks when `tabs.query` or a failed cross-origin fetch would reveal them) without being tied to a tab and without a click on its button, popup, menu item or command in the last 5 seconds (an open popup counts). Paddle says no at once, so the extension still gets those tabs without their address or title, logs a line, and the extension's Extensions menu shows "N site requests auto-denied — Review…", which lists the sites and allows the ones you tick (the site and its `www.` form). Answers are kept in `extension-permissions.json` (per folder name, hand-editable; `"click"` marks a site left to Only When I Click); delete an entry, or use the extension's "Ask About Permissions Again", to change them. If the file is corrupt, no extension loads until it is fixed or deleted.
- **Using them:** each extension with a toolbar action gets a button right of the address bar with its badge; click it for its popup (sign in to a password manager there) and again to close it, right-click for Options, permissions and the extension's own items. A popup opens only from a click, a menu item or a command; an extension can't pop it up on its own. The Extensions menu lists every running extension with its commands, options page, problems and, with `developerTools` on, Inspect Background Page; the load status of every folder is at the bottom. Keyboard shortcuts from an extension's manifest work in browser windows and run before the page sees the key, as in Chrome, except a key one of Paddle's menu items uses, which stays Paddle's. Extension pages open as tabs; sleeping tabs look like Chrome's discarded tabs to them. Failures at startup show in a banner in the window.
- **What extensions can see:** extensions are third-party code. "Allow" usually means every site, signed-in pages included, until you change it. With `tabs`, they see every tab's address and title, sleeping tabs included. They share the browsing cookie store, so `cookies` sees your site cookies. They get no history, bookmarks or downloads API, and Paddle never launches a native app for them (`nativeMessaging` is always refused). Anything that can write to Application Support can pre-approve an extension: the same trust level as `config.json`. An extension and the built-in blocker can both block, so turn one off to compare.
- **Compatibility:** an extension built for Chrome or Firefox (no `browser_specific_settings.safari` in its manifest) loads from a patched clone of its folder in `extension-overlays/`, kept while the folder is unchanged and remade when anything in it changes, with `paddle-prelude.js` running first in its `background.scripts` and first in each of its own content scripts (isolated world only). No content script or site pattern is added, so the sites it asks for are exactly the ones in its manifest. The prelude pins the `browser` and `chrome` globals (WebKit stops delivering events to a context that replaces them, which Proton Pass does at startup) and stubs the missing `runtime.onUpdateAvailable` (calling it throws and aborts an extension's startup). The status line says "compat prelude applied", and names a `service_worker` or `page` background, which the prelude can't go first in and which is left as it is. An extension with nowhere to put the prelude (and no popup fix) loads from its own folder. WebKit drops `webRequestBlocking` (listeners fire, but blocking answers are ignored), `privacy`, `webRequestAuthProvider`, `clipboardRead` and `offscreen`, and Paddle refuses native messaging. For Proton Pass that means no site logos (initials instead), no HTTP basic-auth fill, no clipboard auto-clear, no unlock through the desktop app, and the "disable browser password manager" toggle does nothing; sign-in, vault, autofill, the save prompt and passkeys don't depend on those. Paddle also fixes its popup at 600×430 (WebKit's `tabs.getCurrent` makes it think it opened in a tab, and its lists then draw nothing). Paddle switches on WebKit's `requestIdleCallback` for every page (Chrome and Firefox have it; WebKit ships it off, and Proton Pass's form detector needs it), with a stand-in in the prelude if that private switch is ever missing. Proton's sign-in pages pick how to talk to the extension from the browser name, so give them Firefox's: `"siteUserAgents": {"account.proton.me": "Mozilla/5.0 (Macintosh; Intel Mac OS X 10.15; rv:145.0) Gecko/20100101 Firefox/145.0", "pass.proton.me": <same>}`.
- **Files:** `extensions/` (the folders), `extension-permissions.json` (your answers), `extension-id-salt` (per-install ids; deleting it changes every extension's id and orphans its storage and restored extension tabs), `extension-overlays/` (the patched clones; on the same APFS volume they cost almost no disk, but a folder symlinked in from another volume is copied in full and its status line says "copied, N MB"; safe to delete, remade at the next load). Extension storage lives in `~/Library/WebKit/com.walker.Paddle/WebExtensions/`; deleting an extension's folder keeps its storage and permission entry.
- **Not supported:** native messaging, page context-menu items, private windows unless `extensionsInPrivate` (and `windows.create` never opens one), moving tabs between windows, muting through the tabs API, store installs and updates.

## Other files

- `history.sqlite`: browsing history (History > Show All History, ⌘Y). The address bar suggests open tabs, history and search phrases as you type and completes known hosts inline.
- `bookmarks.json`: bookmarks, as `{"bar": [...], "menu": [...]}` of `{"title": …, "url": …}`; folders have `children` instead of `url`. Paddle adds an `id` to each entry; hand-written entries can leave it out. Edit by hand and Reload Config (an in-app edit also picks up hand edits first), or use Bookmarks > Show Bookmarks (⌥⌘B). ⌘D or the star bookmarks the page to the bar; Edit > Undo reverses bookmark edits. Import/Export Bookmarks… read and write the HTML file Safari, Firefox and Chrome use.
- `favicons/`: site icons, one 32 px PNG per site, refetched weekly. WebKit fetches them (512 KB cap) only from hosts the page itself loaded from, otherwise `/favicon.ico`; SVG icons are skipped. Clear History removes them except for bookmarked sites, and with history off only bookmarked sites' icons are kept. Safe to delete.
- `user.css`: applied to every page.
- `user-filters.txt`: your own Adblock Plus rules (`||host^`, `site.com##.selector`). A selector WebKit cannot parse is dropped and counted as invalid in the status line, not applied in part. Each list compiles on its own, so an `@@` exception here (including `@@||site^$document`) only cancels rules in this file; it does not allowlist a site against EasyList's or EasyPrivacy's blocks. There is no per-site allowlist yet; `contentBlocking: false` turns all blocking off.
- `userscripts/*.js`: Greasemonkey-style scripts (`@match`, `@include`, `@exclude`, `@run-at`, `@noframes`, `@inject-into content`). A file without a header runs everywhere. `GM_*` APIs are not provided.

## Install

`scripts/release.sh` builds a Release signed with Developer ID (hardened runtime, secure timestamp), checks it with `codesign --verify --deep --strict` and refuses a build carrying `get-task-allow`. Every step prints PASS or FAIL, and a summary marks steps that didn't run as SKIP (a step that dies on an unexpected error or Ctrl-C shows as FAIL).

- no flags: build, sign, verify, and zip to `dist/Paddle-<version>-<build>-unnotarized.zip`.
- `--notarize`: also submit a scratch zip with `notarytool` (keychain profile `walker-notary`, or `NOTARY_PROFILE`), staple the app and check it with `spctl`. Only then is `dist/Paddle-<version>-<build>.zip` written, from the stapled app.
- `--install`: also quit a running Paddle, verify a staged copy, swap it into `/Applications/Paddle.app` (the old copy is restored if anything fails), and print the installed version and Gatekeeper's verdict. Without `--notarize` that line says UNNOTARIZED.

`SIGN_IDENTITY` picks a certificate by SHA-1 when more than one Developer ID matches. Once Paddle is in `/Applications`, Paddle > Make Paddle the Default Browser… asks macOS to make it the default; copies run from elsewhere (debug builds) refuse.

## Build

```bash
xcodegen generate && xcodebuild -project Paddle.xcodeproj -scheme Paddle -configuration Debug -derivedDataPath build/DerivedData -allowProvisioningUpdates build
```
