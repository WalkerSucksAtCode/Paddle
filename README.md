# Paddle

A light, hackable Mac browser on Apple's WebKit, the engine Safari uses.

- **Light:** a background tab idle for 5 minutes is frozen first: its page stays in memory but stops running, and shows again with no reload. Frozen tabs that stay idle go to sleep (their web process exits) after 30 minutes, when more than 10 are awake, or right away under memory pressure. Tabs making sound (even if you muted them) or using the camera or mic stay awake; video playing without sound (autoplaying previews and ads) doesn't keep a tab awake. Pages can autoplay video only without sound, as in Safari: sound starts after a click or key press. Restored sessions start with only the visible tab awake. The memory button in the toolbar shows all of Paddle (this tab's share in its tooltip); click it for a per-tab list and where the rest goes (extensions, service workers, the shared GPU and Networking processes, the app itself, cached pages, and helpers such as AutoFill that macOS counts as Paddle's but WebKit doesn't list). The readout updates every 5 seconds only while Paddle is the active app and a browser window is in view, and in whole MB. Timers in hidden pages are throttled more the longer a page stays hidden.
- **Compatible:** identifies as the installed Safari version. Popups and sign-in windows open as tabs with `window.opener` intact, and closing one returns to the page that opened it. Downloads, uploads, camera/mic prompts, HTTP logins, full screen and Web Inspector (right-click > Inspect Element, or the Develop menu: inspector, JavaScript console, element selection, reload without content blockers, empty caches, extension background pages) work. Develop > Responsive Design Mode (⌃⌘R) draws the page at an iPhone, iPad or laptop size (rotatable), always at 1:1 so the page's viewport, pixel ratio and clicks are exact (a device bigger than the window scrolls) under a bar with a device picker and a user agent picker (Paddle, Safari iPhone, Safari iPad, Chrome Android), which wins over `siteUserAgents` and personas until the mode is closed; per tab, not saved. Links to other apps (`mailto:`, `zoommtg:`) open them; when a page rather than a click starts one, Paddle asks first. A frame from another site (a different registrable domain: `drive.usercontent.google.com` is Drive's own) that starts a download also asks first (once per site per session). **Pop-ups:** a window a page opens from a click opens as a tab. One a script opens on its own (Google Drive opens a finished zip this way) loads unseen first: a file goes to Downloads, and a page is cancelled before it renders and offered by the toolbar's Pop-up blocked button (Open, or Always Allow Pop-ups on the site, which writes `sites.<host>.popups: true`; that site's windows then open as tabs). Without WebKit's private click flag, WebKit blocks script windows silently as it used to.
- **Tabs and pages:** The mouse's side buttons go back and forward, like a two-finger swipe. Rename a tab with its right-click menu, by double-clicking it, or Tabs > Rename Tab…; the name survives navigation and relaunch (empty goes back to the page's title). Tab groups work like Chrome's: right-click a tab and choose Add Tab to New Group (or Tabs > Add Tab to New Group), then type its name. A group is a colored label before its tabs, with a colored bar under each of them; click the label to collapse the group (the label then shows how many tabs are hidden), and right-click it to rename it, pick one of nine colors, open a New Tab in Group, Ungroup, Close Group or Move Group to New Window. Drag a tab onto the label or in between the group's tabs to add it, drag it out or choose Remove from Group (Tabs > Remove Tab from Group) to take it out, or use Add Tab to Group in a tab's menu. Pinned tabs can't be grouped. Vertical tabs (View > Vertical Tabs, or Settings > Appearance) move the tabs from the strip into a sidebar beside the page, in every window: pinned tabs form a grid of tiles, groups are collapsible headers (a dot in the group's color, its name and tab count) over their tabs, drag the sidebar's right edge to resize it, and View > Collapse Sidebar (or the button at the top of the sidebar) shrinks it to icons only. Search Tabs, renaming, dragging and the right-click menus work as in the strip. Groups, their names, colors and collapsed state are saved with the session. Spaces split a window's tabs into named sets, each with its own tabs, pins and groups (per window; with two or more, a switcher button with the space's symbol and name starts the tab strip, and the vertical sidebar shows the name above its pins and a row of symbol buttons at the bottom; right-click one to edit or delete it): Tabs > New Space adds one, ⌃1–⌃9 switch (Tabs > Space 1…9, Next Space, Previous Space), Edit Space… opens a popover for the name, symbol (any SF Symbol, from the same searchable grid as a Mosaic's Choose Icon) and tint (a tint colors that window's strip and toolbar while the space is active, with the same strength cap as the chrome tint, so text stays readable), Delete Space closes its tabs into Reopen Closed Tab, and Move Tab to Space moves the selected tab. Search Tabs covers every space, links open in the space of the tab they came from, and spaces are saved with the session (an older session opens as one space, Main). Mosaic shows several tabs of a space at once, tiled: drag a tab from the strip (or a pane by its site icon) over the page area and let go on a pane's edge to put it on that side (the pane gives up half its space), or in the middle to swap two panes or show the tab in that pane's place. While you drag, the panes spring aside into the layout the drop would make and an accent card shows where it lands; dragging out of the window still tears the tab off. Tabs > Mosaic (⌃⌘\) shows the tab with the next one in the strip (or a new New Tab page) and ends the Mosaic when pressed again; a tab's right-click menu has Mosaic with Current Tab (Add to Current Mosaic in one). Up to `mosaicMaxPanes` panes (4; 2 to 6). A Mosaic is one item in the tab strip or sidebar, in place of its tabs: its icon (a grid symbol until you choose one), its name (the focused pane's site until you use Rename Mosaic…) and how many panes it has; click it to show the Mosaic, drop a tab on it to add that tab (it takes half of the largest pane), and its chevron or right-click menu lists its tabs (choose one to focus it), Rename Mosaic…, Choose Icon…, Layout, Even Out Panes, Move Tab Out of Mosaic and End Mosaic. Search Tabs still finds its tabs. While a Mosaic shows, the window toolbar keeps only the profile, extensions, downloads, memory and the menu, and its middle is the Mosaic bar: the empty space around it drags the window (double-click zooms or minimizes, as your system setting says), and the bar has the Mosaic's icon (click to choose one), its name (click to rename) and pane count, the layouts Columns, Rows, Grid and Main and Stack (the current one highlighted), Even Out Panes, Rotate Panes (each tab moves one pane along), Swap Panes (two panes), Add Pane (a New Tab page in half of the largest pane), Reload All Panes, Zoom Pane, a settings menu (most panes in a Mosaic, pane toolbars always or on hover, the space between panes, Mute Other Panes, Mosaic Settings…) and End Mosaic. **Freeform** (the bar's overlapping-rectangles button, or Tabs > Mosaic Layout > Freeform) turns the panes into cards that sit anywhere and may overlap, like windows on a desktop: drag a card by its toolbar, resize it from its sides, bottom or corners, and click one to bring it to the front; cards keep their places as fractions of the content area, so they follow the window's size, and are saved with the session. **Tidy Up** (the wand, or Tabs > Mosaic Layout > Tidy Up) tiles them again in reading order of where they sat, in `mosaicDefaultLayout` (a grid when that is "as dropped"); a layout button does the same in its own layout. Tiled stays the default. Zoom Pane (⌃⌘↩) lets the focused pane fill the Mosaic for now; press it again or focus another tab to get the layout back. Move Pane Left / Right / Up / Down (⌃⌥⇧⌘ and an arrow) swaps the focused pane with its neighbour that way. The same commands are in Tabs > Mosaic Layout and the Tabs menu. Choose Icon offers every SF Symbol on the Mac (read from macOS's own symbol catalog, about 7,000), searchable by name and keyword and filtered by category, with an optional tint from the eight preset colors; Remove Icon goes back to the grid symbol. The icon and tint are saved with the Mosaic. Layout changes, drops, added and removed panes animate with a short spring (none with Reduce Motion). Each pane has its own toolbar with back, forward, reload, an address field with the same suggestions as the window's (open tabs, history and search phrases; arrow keys choose, Return goes or searches in that pane; ⌘L puts the keyboard in the focused pane's field) and × (Remove from Mosaic: the tab leaves it and appears in the strip again; one pane left ends the Mosaic). The focused pane is the selected tab and has a brighter edge; click another pane to focus it, or ⌃⌥⌘ and an arrow (Focus Pane on the Left / Right / Above / Below), or Tabs > Focus Next Pane. ⌥⌘-drag a page to move its pane (`mosaicModifierDrag`), or pick a pane up by a grip or its whole toolbar instead of its site icon (`mosaicPaneGrab`). ⌘T can add a pane (`mosaicNewTab`) and links a pane opens in new tabs can open as panes beside it (`mosaicLinks`), placed by `mosaicNewPanePlacement`; new Mosaics can start in a chosen layout and re-tile as panes come and go (`mosaicDefaultLayout`, `mosaicAutoArrange`). Drag a divider to resize (a side keeps at least 15 %), double-click it to even it out, or Even Out Panes, which gives each pane of a row or column the same share. When the window is too small for every pane (each at least `mosaicMinimumPaneWidth` × `mosaicMinimumPaneHeight`, 260 × 160 pt), only the focused one shows. All of a Mosaic's panes stay awake while it shows. Away from it, a Mosaic freezes and sleeps as one, on its own timers (`mosaicFreezeAfterMinutes`, `mosaicSleepAfterMinutes`; by default the tab ones), timed from the last pane you used: when one pane would freeze or sleep all of them do, and a pane that plays sound, uploads, has unsaved changes or can notify you keeps the whole Mosaic awake; the awake-tab cap and memory pressure also take a whole Mosaic. The Mosaic you just left stays ready (`mosaicStaysReady`): all its pages stay attached, so going back is instant. Settings > Mosaic holds every Mosaic setting. Pinned tabs can't be in a Mosaic. Mosaics and their names are saved with the session (split views from older sessions come back as two-pane Mosaics; `multiViewMaxPanes` and the old action names `toggleSplitView`, `swapSplitSides`, `focusOtherSplitSide` and `removeFromView` are still read). A tab making sound shows a speaker; click it (or Tabs > Mute Tab, ⌃⌘M, or the tab's right-click menu) to mute or unmute. A muted tab stays muted while it sleeps, but not across relaunches. File > Print… (⌘P), File > Save Page As… (⌘S, a `.webarchive`) and View > View Source (⌥⌘U). View Source shows the page's current DOM, after its scripts ran, as text in a new tab; it reads the open page and doesn't download the address again.
- **Appearance and accessibility:** Settings > Appearance sets light, dark or system windows and the tab layout. The text size scales the tabs, toolbar, sidebar, bookmarks bar, address suggestions, find bar and New Tab page, live in every window (pages are not affected). Themes (`theme`: Default, six built-ins, or your own files in `themes/`) color the tab strip or sidebar, toolbar and bars, selected tab, text, accent and New Tab page for light and dark; `accentColor` overrides the theme's accent, and `chromeTint` blends a color over the strip and toolbar, capped (and the cap reported in Settings) wherever more would make text hard to read. Everything applies live to every window, private ones included; the pages themselves are untouched, and a problem in a theme file shows as a notice under the toolbar. A high-contrast selected tab draws a stronger fill and edge by brightness alone, and the default page zoom and a minimum page font size apply to pages. "Always reduce motion" and "Always reduce transparency" apply to Paddle's chrome even when macOS doesn't ask (otherwise Paddle follows System Settings > Accessibility > Display).
- **Profiles:** Settings > Profiles adds profiles such as Work and Personal, each with a name and a symbol (Person, Work, Home, School, Tools, Games, Shopping, Health, Star or Leaf). A window belongs to one profile; File > New Window opens in the front window's profile and File > New Window in Profile lists the others (hidden while there is only one; its items are made from profiles.json, so they have no shortcut action names). Two profiles can't share a name; Add Profile numbers a repeated one. With more than one profile the toolbar shows the window's profile by symbol and name. Separate per profile: cookies, logins, site data, cache, history (and so address suggestions and Frequently visited) and extensions. Shared: bookmarks, New Tab pinned sites, block lists, and settings, except those a profile sets for itself: each profile in Settings > Profiles lists the settings it sets differently, each beside its global value, with Add Setting and a remove button (see `profiles.json` below). Every profile, Personal included, is renamed by editing its name there. A tab can't move between windows of different profiles. Delete a profile in Settings; its windows close and its data is removed.
- **Settings from the address bar:** typing `paddle://settings` opens Settings in a tab (the pane it showed last, or General); `paddle://settings/<pane>` (general, appearance, profiles, tabs, privacy, sites, extensions, shortcuts or advanced) opens it at that pane. Settings has a sidebar of panes and a search field. A window that already has a Settings tab shows that one. `about:settings`, `about:preferences`, `chrome://settings` and `chrome://extensions` work too. Only typed addresses do this: a page or an extension can't open Settings this way.
- **New Tab page:** an empty tab shows your pinned sites as tiles (up to 24) with the address field still focused. Click a tile to open it, Cmd-click or middle-click for a background tab; Tab and Shift-Tab move through the tiles, Return or Space opens one, Delete removes a pinned one. The + tile (Add Site) takes a name and an address (a bare domain gets https://). Right-click a pinned tile to open it in a new tab, edit or remove it, and drag tiles to reorder them. Bookmarks > Add Page to New Tab Page, or the same item in a page's right-click menu, pins the page. Below the grid, Frequently visited shows up to 8 of your most visited sites of the last 30 days (from history, never in private windows); each opens the site's front page, titled with that page's title when you visited it, otherwise the site's address. A near-black icon sits on a light plate in dark mode (and a near-white one on a dark plate in light mode) so it stays visible. Right-click one to pin it or choose Don't Show This Site. `newTabFrequentSites` turns the row off.
- **Toolbar menu:** the menu button (≡) at the right of the toolbar has New Tab/Window/Private Window, History, Bookmarks, Downloads, Extensions, zoom, Print, Import from Browser and Settings.
- **Blocks ads and trackers:** EasyList and EasyPrivacy are converted into WebKit's native content blocker, so blocking costs no extension process.
- **Customizable:** everything lives in plain files in `~/Library/Application Support/Paddle/` (Paddle > Open Config Folder). Edit, then Paddle > Reload Config (⌥⌘,). Paddle > Settings… (⌘,) edits `config.json` for you (see below). Settings opens as a tab in the browser window, and ⌘W closes that tab.

## config.json

Only include the keys you change. A new install starts with `{}`: every key at its default.

Paddle > Settings… (⌘,) writes this file and applies each change at once. The file stays the source of truth: a save changes only the keys you changed, and top-level keys you didn't touch stay byte for byte (formatting, key order and keys Paddle doesn't know). Editing one entry of an object key (`sites`, `shortcuts`, `siteUserAgents`, ...) rewrites that whole key: its other entries keep their values and order, but their spacing and the order of the fields inside them are normalized. A value set back to its default removes the key. A key edited by hand and in Settings is never silently overwritten: if the file changed at that key since Settings read it, nothing is written and Settings offers Use the File's Value or Save Mine. While Settings is open it notices hand edits and shows "config.json has edits Paddle hasn't applied" with Apply Now (the same as Reload Config); saving any change in Settings applies them too. A `config.json` that isn't valid JSON shows the line and column; Paddle keeps the last good settings (an alert on Reload Config) and Settings won't save until it is fixed. A value of the wrong type only falls back to its default (in an object key such as `sites` or `extensionCompat` only that entry is skipped, in a list only that item) and the rest of the file applies; the window, the log and Settings > Advanced > Problems name it, with Reset or Remove. Settings > Advanced has Edit config.json…, Reveal in Finder and Open Config Folder; lists keys Paddle ignores (typos such as `maxAwakeTab`), each with Remove; lists problems in values Paddle reads (errors and warnings by key, with Reset or Remove where that drops only the bad value); and Tidy… shows every key that only repeats its default before removing them: top-level keys, `extensions` entries that are on, `shortcuts` entries equal to the command's default (`"none"` on a command with no default shortcut counts), and fields of a `sites` entry set to Paddle's defaults (not `zoom`: a zoom of 1 can differ from `defaultZoom`). A `sites` entry stays, even as `{}`, until Remove Site. Hand edits show up while Settings is open whether the editor replaces the file or saves in place.

| Key | Default | Meaning |
|---|---|---|
| `homepage` | `about:blank` | Page for a new window (`about:blank` = empty, address bar focused) |
| `newTabPage` | `about:blank` | Page for a new tab |
| `searchTemplate` | `https://duckduckgo.com/?q=%s` | Search URL, `%s` = query |
| `searchSuggestTemplate` | `https://duckduckgo.com/ac/?q=%s&type=list` | Address-bar search suggestions (OpenSearch or DuckDuckGo JSON). Only search words typed key by key are sent, never addresses, paths or pastes; `""` = off |
| `historyDays` | `365` | Days of history kept in `history.sqlite` (0 = no history; the file is kept until you clear it). Settings asks before a shorter value deletes visits and says how many |
| `tabFreezeAfterMinutes` | `2` | Idle minutes before a background tab is frozen (0 = never). Hiding the tab already lets WebKit drop its tiles and decoded images; freezing then stops JavaScript, timers and animations while the page stays in memory, so it shows again with no reload. A sleeping tab's web process exits and it reloads when shown. Never the tab you're looking at, tabs playing sound or using the camera or microphone, pinned tabs (unless `sleepPinnedTabs`), tabs uploading a file (`keepPageWorkRunning`) or sites kept live (`keepNotifyingSitesLive`, `sites.<host>.freeze`). Needs a private WebKit call (`_suspendPage:`); without it nothing freezes. Settings > Tabs & Memory |
| `tabSleepAfterMinutes` | `5` | Idle minutes before a background tab sleeps and its web process exits (0 = never). The tab you just left stays until then; coming back reloads it |
| `maxAwakeTabs` | `8` | Most tabs awake at once, across windows: the most recently used (0 = no cap). A sleeping tab reloads when you return to it, so a small cap makes switching among more tabs than it allows slow. Any further background tab sleeps on the next check, about a minute, least recently used first. Under memory pressure every eligible tab sleeps, largest footprint first. In Low Power Mode or when the Mac runs hot, tabs sleep after at most 5 minutes and the cap is halved (at least 2); when it runs very hot, 1 minute and 2 tabs. Never looser than these values, and a value set to 0 stays off. The Activity popover says when this is in effect |
| `sleepPinnedTabs` | `false` | Let pinned tabs sleep too |
| `keepPageWorkRunning` | `true` | A background tab uploading a file (a `fetch` or `XMLHttpRequest` sending 64 KB or more, or a stream) never freezes or sleeps until the upload ends, except under memory pressure. A page that asks before you leave it (a `beforeunload` listener or `onbeforeunload` handler, which sites add while a form has unsaved changes) may freeze, which keeps the page, but doesn't sleep on the idle or CPU rules; the `maxAwakeTabs` cap and memory pressure still apply. A small page-world script reports both; pages already open pick up a change when they next load. Settings > Tabs & Memory |
| `keepNotifyingSitesLive` | `true` | A site allowed to show notifications (`sites.<host>.notifications` `"allow"`, or allowed when asked this session) never freezes and doesn't sleep for being idle, so its messages keep arriving; the CPU rule, `maxAwakeTabs` and memory pressure still apply. Private windows show no notifications, so this doesn't apply there. `sites.<host>.freeze` overrides it. Settings > Tabs & Memory |
| `cpuSleepPercent` | `30` | A background tab whose web process uses at least this percent of one CPU core for 3 minutes in a row sleeps (0 = off). Tabs sharing a process with another tab, the tab you're looking at, tabs playing sound or using the camera or microphone, and pinned tabs (unless `sleepPinnedTabs`) are left alone. Checked once a minute. Settings > Tabs & Memory |
| `sessionHistoryTabs` | `30` | Tabs whose back/forward history the saved session keeps: the most recently used ones, plus every pinned tab. The rest come back on their page with no Back history. Each kept history is its own file in `sessions/`, rewritten only when it changes; `session.json` names them (0 = pinned tabs only) |
| `resumeMediaOnSelect` | `false` | Switching to a tab resumes its audio and pauses the tab you left. Off, a switch leaves whatever is already playing alone. Settings > Tabs & Memory |
| `linkPreview` | `true` | A real ⌥-click on a link (any frame, target=_blank links too) opens it in a preview over the page instead of following it (so does Preview Link in a link's right-click menu); Tabs > Open Preview as Tab (⇧⌘Return) makes it a tab without reloading, and Escape (when the page doesn't use it) or Tabs > Close Preview closes it. A page's own scripts can't open one. Extensions see it as an inactive tab while it shows, so their content scripts work in it. Off, ⌥-click follows the link. Settings > Tabs & Memory |
| `speculativeLoading` | `true` | Warm a site's connection before you open it: the address bar's top suggestion as you type, a link once the pointer rests on it, and DNS for the page's links (new tabs pick up a change). Never in private windows. Off, nothing connects until you press Return or click. Settings > Privacy |
| `contentBlocking` | `true` | Ad and tracker blocking |
| `filterLists` | EasyList, EasyPrivacy | Adblock Plus lists (https URLs) fetched by Paddle > Update Filter Lists into `filters/` (the two defaults as `easylist.txt` and `easyprivacy.txt`, any other as `<name>-<hash of its URL>.txt`, so two lists with the same file name never collide; a list downloaded before the hash existed is renamed from `<name>.txt` once when no other list could own that file). Only these lists and `user-filters.txt` block: remove a list here and it stops blocking at the next Reload Config (at once from Settings), while its file stays in `filters/` unused until Settings > Privacy & Blocking > Remove Unused List Files moves such files to the Trash (it lists them first). Content blocking in the Activity popover shows a line for each, e.g. `easylist: 61,234 rules (1,830 lines unsupported; 40 style rules; 3 invalid selectors; cached)`, `user-filters: 0 rules (4 comment lines)`, or why a list failed to compile. "Style rules" are `##selector {style}` and `:style(` lines, which inject CSS rather than hide and are never turned into hiding; "invalid selectors" are `##` selectors WebKit's parser refuses (nested `:has`, unbalanced brackets), dropped one by one when a list compiles so that the valid selectors sharing a rule with them keep working |
| `filterUpdateDays` | `7` | Days between automatic downloads of `filterLists`, checked at launch and hourly. Each list is judged by its own file in `filters/`: a list is fetched when its file is missing (new or never downloaded) or older than this, so a failed list is retried at the next hourly check. Failures show under Content blocking in the Activity popover. `0` = only by hand, except a list whose file is missing |
| `scriptlets` | `true` | Run the scriptlets (`##+js(…)` lines) of the lists above and `user-filters.txt`. Paddle ships its own scripts for a fixed set of names (`set-constant`, `abort-on-property-read`, `json-prune`, `no-fetch-if`, `remove-attr` and others, with uBlock Origin's short names); a line can only pick one of them and pass it strings. Other names are counted and skipped. Per-site `contentBlocking: false` turns them off there too |
| `trustedLists` | `[]` | Lists (URLs from `filterLists`) allowed to use `trusted-*` scriptlets. Paddle implements none yet |
| `userAgentSuffix` | `""` | Replaces `Version/… Safari/…` (empty = match installed Safari) |
| `siteUserAgents` | `{}` | Full user agent per site, e.g. `{"example.com": "Mozilla/5.0 …"}`. Settings > Sites offers Chrome and Firefox presets (the whole string is written, so an entry keeps its version) or a custom string. Paddle has a few built-in fixes (`SiteCompat`): Firefox's user agent, at the current version, for `account.proton.me` and `pass.proton.me`. A fix applies only where neither this key nor `sitePersonas` has an entry covering the host; `""` sends WebKit's own and turns the fix off. WebKit's own site quirks (Safari's list) are on as well |
| `sites` | `{}` | Per-site settings by host suffix (`"example.com"` also covers `www.example.com`; the longest match wins each field): `{"example.com": {"zoom": 1.25, "javaScript": false, "autoplay": "allow" / "muted" / "block", "contentBlocking": false, "location": "ask" / "allow" / "deny", "notifications": "ask" / "allow" / "deny", "httpsOnly": false, "popups": true, "darkMode": true, "freeze": "auto" / "never" / "always"}}`. Every field is optional; unset means Paddle's default (zoom `defaultZoom`, JavaScript on, `"muted"`: media may autoplay without sound, blocking on, `"ask"`, `httpsOnly` true: `false` lets the site load over http://, `popups` false: see Pop-ups, `darkMode` unset follows global `darkMode`, `freeze` `"auto"`: background tabs freeze as usual unless `keepNotifyingSitesLive` keeps the site live; `"never"` keeps them running and out of idle sleep like a live site; `"always"` lets them freeze even when they may notify; sound, camera, microphone and uploads still keep a tab running). JavaScript and autoplay apply from the next page load; `"allow"` and `"block"` autoplay need a private WebKit setting and act as `"muted"` without it. Zoom In / Zoom Out / Actual Size remember the zoom here (under the entry that sets it, else the host without `www.`), and open tabs on the site follow. `"contentBlocking": false` compiles an exception for the host and its subdomains into every block list (a subdomain can't turn it back on). Location `"ask"` asks once per site per session; the prompt's "Remember" writes `"allow"` or `"deny"`. Private windows write nothing here: their zoom lasts until the last private window closes, and their location prompt has no "Remember". `"notifications"` works like location: `"ask"` asks once per site per session, and the prompt's "Remember" writes `"allow"` or `"deny"`; macOS asks once, on the first allowed site, whether Paddle may post notifications, and private windows never show them. Settings > Sites has a row per entry with its effective values (a tooltip says whether each comes from the entry, a parent domain's entry or the default; setting a value other than zoom back to what the host would get anyway removes that field (a zoom stays, since it is a choice whatever `defaultZoom` is), and the entry stays, even as `{}`, until Remove Site), Add Site (writes `{}`; a pasted URL gives its host), Clear Data… (after a confirmation, removes the cookies, caches and storage of the site's whole domain from the ordinary data store) and "This session": camera, microphone, location, notification and download answers, never written to disk, each host with Forget so it asks again. User agents stay in `siteUserAgents` |
| `sitePersonas` | `{}` | Presents Paddle to a site as Chrome or Firefox, by host suffix (`{"example.com": "chrome"}`; the longest match wins, so `"none"` on a subdomain opts it back out). The site's navigations send the Settings > Sites preset for that browser, and the JavaScript of each frame whose own host matches sees its identity: for Chrome `navigator.vendor` "Google Inc.", `navigator.userAgentData` on secure pages, `window.chrome` and Chrome's five PDF plugin entries; for Firefox an empty vendor, `oscpu` and `buildID`, and no `window.chrome` or `userAgentData`. Both apply from the next page load. Limits: no `Sec-CH-UA` client-hint headers; the engine, CSS and TLS fingerprints still say WebKit; a `siteUserAgents` entry for the host wins the user agent string, while the page's JavaScript keeps the persona |
| `showTabMemory` | `true` | Memory readout in the toolbar. Off, Paddle doesn't sample memory at all unless Settings is showing it |
| `httpsOnly` | `true` | Load `http://` pages over `https://` (an explicit port 80 is dropped). When the secure load fails to connect (no TLS, bad certificate, timeout, refused) or the site sends you back to `http://`, Paddle shows its own notice instead of the page, with Go Back, Continue to HTTP (that host, until Paddle quits, private windows included) and Always Allow HTTP (writes `sites.<host>.httpsOnly: false`; not offered in private windows). Local addresses are exempt: `localhost`, `*.local`, `*.home.arpa`, `*.internal`, names without a dot, private and link-local IP addresses. Per site: `sites.<host>.httpsOnly: false`. Settings > Privacy & Blocking |

## Private windows

File > New Private Window (⇧⌘N). The window's address field is tinted and labelled **Private**, and its title (Window menu, Mission Control) is always "Private Window", never a page title, since other apps can read window titles.

- **Data:** all private windows share one temporary cookie and site-data store, separate from your normal one. It is thrown away when the last private window closes; the next private window starts empty.
- **Nothing saved:** no history, no favicons, not in `session.json` or `sessions/`, and closed private tabs aren't offered by Reopen Closed Tab. Downloads are saved as files as usual; Paddle keeps no download list on disk, and private downloads leave the downloads popover when the last private window closes (one still running then leaves when it ends). Other windows' memory popovers count private tabs but don't list their titles.
- **Still works:** content blocking, `user.css` and userscripts as in normal windows. Bookmarks can be added. Address-bar suggestions read your history and bookmarks but nothing typed is recorded; a private window's tabs are suggested only in that window.
- **Extensions:** off in private windows unless `extensionsInPrivate` is `true` or the extension's `"private"` is `true`; `"private": false` keeps it out either way (Settings > Extensions has both switches). An extension not allowed there can't see private windows or tabs, has no toolbar button or commands there, and its pages don't open there. While such a window is in front, that extension's Run Action, Show Popup and commands are disabled. An allowed extension can open a private window with `windows.create({incognito: true})`.
- Links from other apps open in a normal window.

## Moving from another browser

File > Import from Browser… lists the Safari, Chrome (and Brave, Edge, Arc, Chromium) and Firefox profiles it finds and brings over the things below, each with its own checkbox (only the ones that profile has are enabled). It reads history from a copy of the database and changes nothing in the old profile, and the result sheet says what was imported and what was skipped and why. Paddle never reads Keychain, saved passwords, cookies or any other part of the profile.

- **Settings:** the default search engine, the home page and the bookmarks bar, written to `config.json` the way Settings writes it (a key you edited by hand meanwhile is not overwritten). The engine must be one Settings offers (DuckDuckGo, Google, Bing, Brave, Kagi, Ecosia); any other is reported and your engine stays. A home page comes over only where the old browser really opens one in new windows. New tabs come over only from Safari, when its new tabs open the home page.
- **History:** the newest 200,000 visits with their original dates, web pages only (`http` and `https`; internal pages, files and extension pages are skipped). Visits already in Paddle's history are skipped, so importing twice adds nothing, and visits older than `historyDays` are skipped too (they would be deleted again at once). With `historyDays` at 0 nothing is imported.
- **Where from:** Safari `~/Library/Safari/History.db` and its preferences in `~/Library/Containers/com.apple.Safari/`; Chrome and the browsers built on it, `History` and `Preferences` in each profile folder under `~/Library/Application Support/`; Firefox, `places.sqlite`, `prefs.js` and `search.json.mozlz4` in each profile listed in `profiles.ini`.
- **Other browsers' data is protected by macOS too, not only Safari's:** Chrome, Edge and Firefox keep theirs in folders macOS guards, as Safari does. Without Full Disk Access Paddle can't read them, and each shows as needing it in the list (Safari always does, since its files can't be checked without the permission). To import from one, allow Paddle in System Settings > Privacy & Security > Full Disk Access, or export bookmarks as HTML (see Bookmarks). Paddle never asks for the permission itself.
- **Bookmarks:** read directly, no export needed: Chrome and the browsers built on it (the profile's `Bookmarks` JSON), Firefox (`places.sqlite`), Safari (`~/Library/Safari/Bookmarks.plist`, which needs Full Disk Access). The bookmarks bar goes to Paddle's bar and everything else into a folder named "Imported from <profile>". Bookmarks already in Paddle are skipped, addresses that aren't web pages are skipped and counted, and one Edit > Undo Import Bookmarks takes the whole import out. An exported bookmarks HTML file still works as the fallback: Bookmarks > Import Bookmarks… (the sheet has a button for it).
- **Open tabs:** off by default, because it opens windows. Chrome-family browsers (from the profile's `Sessions` files) and Firefox (`sessionstore-backups/recovery.jsonlz4`); Safari isn't supported yet, and a Chrome session that is encrypted can't be read. Each old window becomes a new Paddle window; its tabs stay asleep until you show them, web pages only, up to 500 tabs in all. The import doesn't write `session.json` itself; the new windows are part of your session like any other and come back at the next launch.
- **Site settings:** per-site zoom, notification and location answers, JavaScript off and autoplay, written to `sites` in `config.json`. Chrome-family browsers give zoom, notification and location answers and JavaScript off (from `Preferences`); Firefox gives zoom, notification and location answers and autoplay (from `content-prefs.sqlite` and `permissions.sqlite`). It only fills in: a site that already has a value for a field in Paddle keeps it, and a value equal to Paddle's default isn't written. Wildcard patterns, ports and other non-plain hosts are skipped and counted. A leading `www.` is dropped from the host.
- **Passwords:** Paddle never reads them. Export them from the old browser or your password manager as a file, import that file into your password manager extension, then delete the file, since it holds your passwords in plain text. For Proton Pass, import in the Proton Pass extension's settings (or in its web app at pass.proton.me); see Proton Pass's import help for the formats it accepts and the exact steps. Old browsers: Chrome exports from its password manager's settings, Firefox from `about:logins`, Safari from the Passwords app's File menu.
- **Cookies and sessions:** cookies and sign-ins are not imported; you sign in to each site again. Open tabs are the exception above.
- **Extensions:** the sheet lists the profile's extensions and nothing is installed unless you tick it. Ticked ones from the Chrome Web Store or addons.mozilla.org reinstall one at a time through Paddle's store installer after you press Done (closing the sheet any other way installs nothing), each asking for its permissions as usual; ones Paddle already has can't be ticked. Edge Add-ons, hand-added (unpacked) ones and anything without a store link are listed as not installable. Safari extensions come inside Mac apps, so Paddle can't install them. Their storage starts empty, so sign in to each extension again.

## Extensions

Paddle runs WebExtensions (the Chrome and Firefox add-on format) on WebKit's own extension support, the same engine Safari uses for web extensions. Manifest V3 and whatever V2 support WebKit provides.

- **Installing:** put each unpacked extension in its own folder in `extensions/` (Extensions > Open Extensions Folder): a folder with `manifest.json` at its root, or a folder holding exactly one such folder (the usual unzip layout). Zips and `.crx` files must be unzipped first; a folder without a manifest gets a status line, not a load. Paddle > Reload Config picks up added, removed, enabled and disabled folders; Extensions > Reload Extensions reloads everything, edited files included.
- **Installing from the Chrome Web Store:** Extensions > Install from Link… takes a Chrome Web Store link (`https://chromewebstore.google.com/detail/…`) or a 32-letter extension id; on a store page, a bar under the toolbar offers "Install <name> in Paddle" (or says it is installed). Paddle downloads the package from Google's update service (no cookies, 100 MB cap, redirects only to Google's download servers) and checks Google's Web Store signature and the developer's key before unpacking; it also checks the archive for unsafe names, links and anything the archive doesn't list. A package that fails any check is refused and nothing is installed. It lands in its own folder in `extensions/`, named from the extension, and is recorded in `extension-sources.json`; then the extension asks for its permissions as usual. It runs as Chrome, with its store id when it needs one (sign-in through `identity`, `oauth2`, `externally_connectable`). Installing the same extension again offers to replace it when the version differs (its settings and data stay) and says it is already installed otherwise. Updates are described under Updates.
- **Installing from Firefox Add-ons:** Extensions > Install from Link… and the bar on an addons.mozilla.org add-on page take an add-on link (`https://addons.mozilla.org/<locale>/firefox/addon/<slug>/`). Paddle looks the add-on up on addons.mozilla.org, downloads its current `.xpi` (https, redirects only to Mozilla's add-on hosts, 100 MB cap) and checks it against the file's size and SHA-256 from that lookup. Then it checks the archive as for a Chrome package and Mozilla's signature: every file's SHA-256 in `META-INF/manifest.mf`, the manifest's digest in `mozilla.sf`, and the CMS signature in `mozilla.rsa`, made by a certificate named for the add-on's id, which `manifest.json` must also name as its gecko id. That certificate must chain to Mozilla's add-on root, which Paddle bundles (`root-ca-production-amo`, the same certificate Firefox carries); if the bundled root were missing or altered, an add-on would say its chain isn't verified and ask "Install anyway?", and its record would say `"verified": false`. Installed add-ons run as Firefox and are recorded like Chrome installs.
- **Updates:** each extension installed from a store is checked once a day, at launch and hourly, while `extensionUpdates` is on in config.json. The check asks the store: Google's update check for a Chrome Web Store extension, the add-on's lookup on addons.mozilla.org. A newer version is downloaded and checked exactly as an install is, and it must be the version the store named and newer than the installed one (downgrades are refused). If it asks for nothing you haven't granted, and for an add-on Mozilla's certificate chain is verified, it replaces the installed copy quietly: same folder, settings and data, then it reloads. If it asks for more, the installed copy keeps running, the new copy waits in `extensions/.staged-<folder>/`, and the update alert names what is new. Allow swaps it in and grants those; Don't Allow discards it, and Paddle doesn't ask again for that version. An add-on whose chain isn't verified always gets the alert, as it does at install. Extensions > Check for Extension Updates checks every store install now and shows a summary. Each folder's result (up to date, updated to X, update X waiting for permission, or the reason it failed) is listed in the Extensions menu and the log. Folders you put in by hand are never updated.
- **Permissions:** before an extension first runs, Paddle lists what it wants and offers **Allow** (everything it asks for), **Only When I Click** (its APIs, but no site until you click its button, which grants that tab for that click) or **Don't Allow**. A running extension asking for more gets the same prompt; a site it is refused for isn't asked about again until relaunch, whichever page on the site it asks about. One kind of request never shows an alert: an extension asking to see tabs on sites it hasn't been granted (WebKit asks when `tabs.query` or a failed cross-origin fetch would reveal them) without being tied to a tab and without a click on its button, popup, menu item or command in the last 5 seconds (an open popup counts). Paddle says no at once, so the extension still gets those tabs without their address or title, logs a line, and the extension's Extensions menu shows "N site requests auto-denied — Review…", which lists the sites and allows the ones you tick (the site and its `www.` form). Answers are kept in `extension-permissions.json` (per folder name, hand-editable; `"click"` marks a site left to Only When I Click); delete an entry, or use the extension's "Ask About Permissions Again" (its Extensions menu, or Settings > Extensions, which also works for a declined extension that isn't running), to change them. If the file is corrupt, no extension loads until it is fixed or deleted.
- **Using them:** each extension with a toolbar action gets a button right of the address bar with its badge; click it for its popup (sign in to a password manager there) and again to close it, right-click for Options, permissions and the extension's own items. A popup opens only from a click, a menu item or a command; an extension can't pop it up on its own. The Extensions menu lists every running extension with its commands, options page, problems and, with `developerTools` on, Inspect Background Page; the load status of every folder is at the bottom. Keyboard shortcuts from an extension's manifest work in browser windows and run before the page sees the key, as in Chrome, except a key one of Paddle's menu items uses, which stays Paddle's. Extension pages open as tabs; sleeping tabs look like Chrome's discarded tabs to them. `tabs.move` with a window id and `windows.create` with tab ids move tabs between windows, page and history included; a window left with no tabs closes, as in Chrome. `windows.create({incognito: true})` opens a private window for an extension allowed in private windows, and tabs move only between windows of the same kind. An extension with access to the page (its site, or `activeTab`) adds its `contextMenus` items to the page's right-click menu, several under a submenu named after the extension, as in Safari. Failures at startup show in a banner in the window.
- **What extensions can block:** a declarativeNetRequest extension blocks with its rules, and WebKit applies them: the rule files in its manifest and the rules it adds while it runs. An extension that asks for `webRequestBlocking` without rule files doesn't block anything here, because WebKit delivers the requests to its listeners and ignores their answers: whatever it would block or change still loads. That covers uBlock Origin's MV2 build, which blocks only that way, and extensions that ask for it for other reasons, such as Proton Pass's HTTP auth handling (see Compatibility). Its permission prompt says so when you first allow it, and the log records it at each load. Its content scripts still run, so the hiding they do on a page still works. Paddle's own lists block whatever the extensions do: EasyList and EasyPrivacy, the optional uBlock Origin lists (Settings > Privacy & Blocking > Filter lists > uBlock Origin lists > Add) and `user-filters.txt`.
- **What extensions can see:** extensions are third-party code. "Allow" usually means every site, signed-in pages included, until you change it. With `tabs`, they see every tab's address and title, sleeping tabs included. They share the browsing cookie store, so `cookies` sees your site cookies. They get no history, bookmarks or downloads API. Native messaging reaches only Paddle's own compatibility channel (`com.walker.paddle.compat`, answered inside Paddle); any other app id gets Chrome's "Specified native messaging host not found.", and Paddle never launches an app for an extension. Anything that can write to Application Support can pre-approve an extension: the same trust level as `config.json`. An extension and the built-in blocker can both block, so turn one off to compare.
- **Compatibility:** Paddle runs each extension as the browser it was built for (`extensionCompat` overrides it per folder). A Firefox build (a gecko id and a background that isn't only a service worker) runs as Firefox: its pages are `moz-extension://<uuid>/`, its own views send Firefox's user agent, and `runtime.getBrowserInfo` says Firefox. Its `runtime.id` stays the private id it always had, so its storage carries over; saved tabs on its old `webkit-extension://` pages move to the new address (without their back history). Anything else that isn't a Safari build runs as Chrome: `chrome-extension://` pages under a private id in Chrome's a–p letters, Chrome's user agent and `navigator.userAgentData`, `chrome.app`, and no `browser` object. Safari builds run untouched (`native`). Both personas load from a patched clone in `extension-overlays/` (kept while the folder is unchanged; its two generated scripts are rewritten at every load): `paddle-prelude.js` runs first in the background (first in `background.scripts`, through a `paddle-sw.js` wrapper next to a service worker, or by a script tag in every page, popups, options and a background page included) and `paddle-content.js` first in each of its own isolated-world content scripts. No content script or site pattern is added. The prelude fills in what WebKit lacks: Chrome's enums and constants, inert `runtime.onUpdateAvailable` / `onSuspend` / `onRestartRequired` events, `requestUpdateCheck`, `runtime.getManifest()` as the extension wrote it, `permissions` that leave out Paddle's own grant and answer names WebKit doesn't know, `i18n.getMessage("@@ui_locale")`, `action.getUserSettings`, `tabs.getCurrent()` as undefined in the popup, an empty read-only `storage.managed`, the MV2 `extension.sendRequest` / `getURL` aliases, `runtime.onInstalled` with `install` on a folder's first run (WebKit never sends it; `extension-installs.json` remembers), and `requestIdleCallback`. If a background fails to load with the prelude, Paddle loads that extension again from its own folder for the rest of the session and its status says "compat off". User agents: popups, extension-page tabs and a background page send the persona's; a service worker's own requests still send Safari's. WebKit drops `webRequestBlocking` (listeners fire, but blocking answers are ignored), `privacy`, `webRequestAuthProvider`, `clipboardRead` and `offscreen`. For Proton Pass that means no site logos (initials instead), no HTTP basic-auth fill, no clipboard auto-clear, no unlock through the desktop app, and the "disable browser password manager" toggle does nothing; sign-in, vault, autofill, the save prompt and passkeys don't depend on those. Proton Pass's popup gets its full 600×430 layout from that `tabs.getCurrent` fix; with `"persona": "none"` it lays itself out at tab size (356×338), since that clone has no prelude in its pages. Paddle switches on WebKit's `requestIdleCallback` for every page (Proton Pass's form detector needs it). Proton's sign-in pages pick how to talk to the extension from the browser name, so Paddle sends `account.proton.me` and `pass.proton.me` Firefox's user agent by default (see `siteUserAgents`); an entry of your own for those hosts replaces it.
- **Files:** `extensions/` (the folders), `extension-permissions.json` (your answers; another profile's are in `profiles/<id>/extension-permissions.json`), `extension-id-salt` (per-install ids; deleting it changes every extension's id and orphans its storage and restored extension tabs), `extension-sources.json` (which folders came from a store, with the store id, version, install date, the last store check, a hash of each file, `verified`, which is `false` for a Firefox add-on whose certificate wasn't checked, and `declinedVersion`, an update you refused; a folder's record is dropped when the folder is deleted), `extension-installs.json` (when each folder first ran, for `runtime.onInstalled`; made from the permissions file the first time, so extensions that ran before it existed don't count as new), `extension-overlays/` (the patched clones; on the same APFS volume they cost almost no disk, but a folder symlinked in from another volume is copied in full and its status line says "copied, N MB"; safe to delete, remade at the next load). Extension storage lives in `~/Library/WebKit/com.walker.Paddle/WebExtensions/` (`Default` for the default profile, the profile's id for another); deleting an extension's folder keeps its storage and permission entry.
- **Not supported:** native messaging to real apps, page context-menu items from an extension without access to the page (Chrome shows them anyway; Paddle follows Safari), muting through the tabs API.

## Other files

- `history.sqlite`: browsing history (History > Show All History, ⌘Y; File > Import from Browser… adds another browser's). The address bar suggests open tabs, bookmarks, history and search phrases as you type. Pages rank by how well they match (the site's address itself, then the start of its address, then a word of its title, then anywhere), then open tab, bookmark, history, then how often and recently you visited. It completes known hosts inline.
- `bookmarks.json`: bookmarks, as `{"bar": [...], "menu": [...]}` of `{"title": …, "url": …}`; folders have `children` instead of `url`. Paddle adds an `id` to each entry; hand-written entries can leave it out. Edit by hand and Reload Config (an in-app edit also picks up hand edits first), or use Bookmarks > Show Bookmarks (⌥⌘B). ⌘D or the star bookmarks the page to the bar; Edit > Undo reverses bookmark edits. Import/Export Bookmarks… read and write the HTML file Safari, Firefox and Chrome use.
- `newtab.json`: the New Tab page's pinned sites, `{"sites": [{"title": …, "url": …}], "hiddenFrequent": ["host", …]}` (up to 24 web pages; `hiddenFrequent` lists hosts removed from Frequently visited). Paddle adds an `id` to each site; hand-written ones can leave it out. Bookmarks > Add Page to New Tab Page pins the open page (and unpins it again); Edit > Undo reverses tile edits. Edit by hand and Reload Config.
- `feeds-cache.json`: the New Tab News section's last stories and when they were fetched (`newTabFeeds`); safe to delete.
- `bridge/control.sock`: the control bridge's Unix socket (mode 0600, in its own folder, mode 0700); present only while `controlBridge` is on. A very long home folder puts it at `<temp dir>/paddle-<uid>/control.sock` instead (parent mode 0700).
- `profiles.json`: the profiles, `{"profiles": [{"id": …, "name": …, "symbol": "work", "extensions": {"folder": true}, "settings": {…}}]}`. `settings` is the profile's own config.json values, written like config.json: `{"searchTemplate": "https://duckduckgo.com/?q=%s", "tabSleepAfterMinutes": 15, "theme": "ocean", "sites": {"example.com": {"zoom": 1.25}}}`. A key it leaves out is config.json's value; `sites` merges per site and per field, so a profile's zoom for a site keeps config.json's JavaScript setting for it. Windows of the profile (and the default profile's settings in private windows) run with the result. Keys a profile can set: `homepage`, `newTabPage`, `searchTemplate`, `searchSuggestTemplate`, `newTabFrequentSites`, `historyDays`, `askWhereToDownload`, `downloadFolder`, `theme`, `accentColor`, `chromeTint`, `chromeTintStrength`, `tabFreezeAfterMinutes`, `tabSleepAfterMinutes`, `sleepPinnedTabs`, `cpuSleepPercent`, `keepPageWorkRunning`, `keepNotifyingSitesLive`, `linkPreview`, `resumeMediaOnSelect`, and these `sites` fields: `zoom`, `javaScript`, `autoplay`, `location`, `notifications`, `popups`, `httpsOnly`, `freeze`. Every other key is shared by all profiles and ignored here with a note under the profile in Settings: block lists, scriptlets, `sites.<host>.contentBlocking`, `sites.<host>.darkMode`, `sitePersonas`, `siteUserAgents`, `userAgentSuffix`, `underlineLinks` and user.css go into the one WebKit content controller every profile shares; `maxAwakeTabs` caps awake tabs across all windows; light/dark appearance, text size and accessibility are app-wide; so are tab layout, shortcuts, the Develop menu and the control bridge. A value of the wrong type uses config.json's default, as in config.json, and is listed under the profile. Zooming a site whose zoom the profile sets saves to the profile, not config.json. The default profile ("Personal", id `default`, renamable, not deletable) keeps the data Paddle has always used. Each other profile has its own cookies, logins, site storage and cache (a WebKit data store named by its id) and its own `profiles/<id>/history.sqlite`; address suggestions, History, Clear History (which clears only the front window's profile) and the New Tab page's Frequently visited follow the window's profile. Bookmarks, pinned New Tab sites, config.json, block lists, favicons and downloads are shared. A window belongs to one profile (saved in `session.json`) and a tab never moves to a window of another profile. Symbols: person, work, home, school, tools, games, shopping, health, star, leaf. Extensions: the default profile runs the folders config.json's `extensions` leaves on; another profile runs only the folders on in its own `extensions` here (none at first; Settings > Extensions, opened from one of its windows, switches them). Each profile has its own extension storage (signed in to a password manager in one profile, not in another), its own permission answers (`profiles/<id>/extension-permissions.json`), popups and background pages; the extension folders, updates, store installs and overlays are shared; a new extension installed from the store in another profile's window is on only in that profile (`extensions.<folder>` false in config.json). This run's permission answers (camera, microphone, location, notifications, downloads) are kept per profile too. If profiles.json can't be read at launch, windows of other profiles stay closed and are kept in `session.json` until Reload Config reads it; a profile removed from the file by hand has its windows closed at Reload Config (its data stays on disk). Deleting a profile removes its data store, its extension storage and its `profiles/<id>/` folder. Private windows ignore profiles and run the default profile's extensions.
- `favicons/`: site icons, one 32 px PNG per site, refetched weekly. Sites New Tab shows as tiles also get a 128 px icon in `favicons/large/` (the largest `apple-touch-icon`, else an icon link of 96 px or more, else the site's `/apple-touch-icon.png`; sites with none keep the small one). WebKit fetches them (512 KB cap) only from hosts the page itself loaded from, otherwise `/favicon.ico`; SVG icons are skipped. Clear History removes them except for bookmarked sites, and with history off only bookmarked sites' icons are kept. Safe to delete.
- `user.css`: applied to every page.
- `user-filters.txt`: your own Adblock Plus rules (`||host^`, `site.com##.selector`). A selector WebKit cannot parse is dropped and counted as invalid in the status line, not applied in part. Exceptions here work across lists: every `@@` line (including `@@||site^$document`, which turns blocking off on that site) and every `site.com#@#.selector` line is appended to each downloaded list when it compiles, so they cancel EasyList's and EasyPrivacy's blocks and hiding too. Changing them recompiles every list at the next Reload Config; changing only other lines recompiles just this file. `contentBlocking: false` turns all blocking off.
- Filter syntax: `||host^`, `|anchor|`, `*`, `^`, options WebKit can express (`third-party`, `domain=`, resource types, `match-case`, `important`, `$document` on `@@`, with or without `||`), `##` hiding with `#@#` exceptions, and `/regex/` rules. `subdocument` / `frame`, and rules with only negated types (`$~script`), block frames but never a page you navigate to. `$important` blocks beat the list's own `@@` lines; your `@@` lines and sites with blocking off still beat them. A regex is rewritten for WebKit only when the result matches exactly the same URLs (`\d` and `\w` become classes, a `-` next to them in a class is a hyphen as in JavaScript, `{2,4}` is written out up to 32 copies, `(a|b)` becomes one rule per alternative, up to 32, each at most 200 characters); lookarounds, `\b`, backreferences, backwards ranges like `[z-a]` and anything longer are refused, counted as "regex: N translated, M refused" in the status line. If WebKit still refuses a list that has regex rules, it is compiled once more without them and the status line adds "regex rules left out: WebKit refused them (reason)". Selector lists are split, so `site.com#@#.sidebar` also excepts the `.sidebar` of `##.ad, .sidebar`. A generic `##.ad` with `site.com#@#.ad` keeps hiding everywhere but that site; a `site.com##.ad` that a `#@#` names (or names a subdomain of) is dropped for that rule. Scriptlets (`##+js`), extended selectors and options like `redirect`, `csp`, `removeparam`, `replace=`, `header=` are counted as unsupported, never approximated; the Activity popover's "Not covered" line for each list says how many of each kind.
- Startup blocking: windows and tabs open at once, but a tab's first page waits until every block list is installed, at most 3 s. Lists compile in parallel and each starts blocking as soon as it is compiled (cached lists load in milliseconds); a page that loaded during a slower compile reloads once when the lists are in, unless it came from a form post, is playing media or using the camera or microphone, or you typed into it. On a first launch (a default list's file missing from `filters/`) Paddle copies the EasyList and EasyPrivacy snapshots bundled in the app, fetched 12 Oct 2026 (`! Version: 202610121715`), so blocking starts without the network; the file is dated by that version, so the automatic update replaces it once it is `filterUpdateDays` old (with `filterUpdateDays: 0`, only Update Filter Lists does).
- `themes/*.json`: chrome color themes (Settings > Appearance > Open Themes Folder). The file's name, without `.json`, is the theme's name and its `theme` value; a file named like a built-in (or `default`) is skipped. Format: `{"light": {...}, "dark": {...}}`, each with `tabStrip`, `toolbar`, `selectedTab`, `text`, `secondaryText`, `accent` and `newTabBackground` as `"#rrggbb"`. Leave a mode out and that appearance keeps the default look; a missing or bad color keeps the default look for that surface (a warning, e.g. `themes/x.json: dark.toolbar: not a #rrggbb color`); unknown keys are ignored; a file that isn't a JSON object is a warning and the theme falls back to Default. A theme is still applied if it breaks the contrast rules, with a warning naming the pair and ratio (e.g. `dark text on tabStrip 3.10:1, needs 4.5:1`). Rules: `text` 4.5:1 on `tabStrip`, `toolbar`, `selectedTab` and `newTabBackground`; `secondaryText` 4.5:1 on `tabStrip`, `toolbar` and `newTabBackground`; `accent` 3:1 on `toolbar` and `newTabBackground`; `selectedTab` 1.4:1 against `tabStrip`. Reload Config re-reads the folder.
- `userscripts/*.js`: Greasemonkey-style scripts (`@match`, `@include`, `@exclude`, `@run-at`, `@noframes`, `@inject-into content`). A file without a header runs everywhere. `GM_*` APIs are not provided.

## Control bridge (Claude)

Off by default (`controlBridge`). When on, Paddle listens on an owner-only Unix socket (`bridge/control.sock`, never a TCP or UDP port, so no web page can reach it) and the `paddle-mcp` helper inside the app relays a Claude session's MCP traffic to it. Add it once:

```bash
claude mcp add paddle -- /Applications/Paddle.app/Contents/Helpers/paddle-mcp
```

Tools (tab and window ids come from `paddle_state`):

- `paddle_state`: windows (profile, spaces, the link preview's URL and title or null) and their tabs (id, title, URL, pinned, group, asleep, selected, space), the build and the config warning count. Titles and URLs are marked as untrusted page content.
- `page_text`, `page_snapshot`: an awake http(s) or about: tab's visible text (default 20,000 characters) or a PNG made by WebKit (at most 1600 px wide; works in the background).
- `window_snapshot`: a window's own drawing with its page (and the link preview over it), best effort.
- `read_config`: config.json and its warnings. `logs`: Paddle's own log entries (default the last 5 minutes, 200 entries), private values redacted.
- `open_url` (http, https, about:blank, paddle://settings; `"in": "preview"` opens an http(s) address in the window's link preview over its selected tab), `select_tab` (switches space, wakes the tab), `close_tab`, `reload_tab`, `wait_for_load` (default 15 s).
- `menu_action`: any menu command by its action name (as in `shortcuts`), refused when hidden or disabled. Never `quit`, the clipboard (`cut`, `copy`, `paste`, `pasteAndMatchStyle`, `useSelectionForFind`), file import and export (`importFromBrowser`, `importBookmarks`, `exportBookmarks`, `savePage`, `print`), `installExtensionFromLink`, `makeDefaultBrowser` or `hideOthers`.
- `set_config`: top-level config.json keys through the same conflict-checked writer as Settings; values Settings would refuse are refused. Settings-only, never through the bridge: `controlBridge`, `controlBridgeScripts`, `extensions`, `extensionsInPrivate`, `extensionCompat`, `searchTemplate`, `searchSuggestTemplate` (what runs, and where searches go, in private windows too).
- `run_js` (only with `controlBridgeScripts`, Allow page scripts): a script in an isolated content world on an http(s) tab, 10 s limit, returning its JSON result. `document.cookie`, `cookieStore`, password field values and frames' documents are guarded there, and the site's cookie values (8 characters or more) are replaced by `[cookie]` in the result. A guard, not a sandbox: a script can still reach what the page's own scripts can (non-HttpOnly cookies through a frame's global, a password field after changing its type), and an encoded copy gets past the redaction.

While a session is connected every window's toolbar shows "Claude connected"; click it to disconnect. Settings > Advanced shows the setup command with a Copy button, the connected sessions and the last 50 calls.

Limits: private windows are invisible (not listed, not reachable); no tool reads the keychain, the clipboard, downloads or files outside Paddle's support folder; no tool but `run_js` reaches cookies or typed passwords (see above); page text, titles and script results are marked as untrusted page content. With Paddle not running or the switch off, the helper prints a JSON-RPC error and exits.

## Not supported

- **Web Push:** notifications from a site while it is closed. Delivering them needs an Apple push entitlement that a third-party browser doesn't get by default.
- **Apple Pay and Payment Request:** both need an Apple entitlement a third-party browser doesn't get by default, so they are not available in Paddle.

## Install

`scripts/release.sh` builds a Release signed with Developer ID (hardened runtime, secure timestamp), checks it with `codesign --verify --deep --strict` and refuses a build carrying `get-task-allow`. Every step prints PASS or FAIL, and a summary marks steps that didn't run as SKIP (a step that dies on an unexpected error or Ctrl-C shows as FAIL).

- no flags: build, sign, verify, and zip to `dist/Paddle-<version>-<build>-unnotarized.zip`.
- `--notarize`: also submit a scratch zip with `notarytool` (keychain profile `walker-notary`, or `NOTARY_PROFILE`), staple the app and check it with `spctl`. Only then is `dist/Paddle-<version>-<build>.zip` written, from the stapled app.
- `--install`: also quit a running Paddle, verify a staged copy, swap it into `/Applications/Paddle.app` (the old copy is restored if anything fails), and print the installed version and Gatekeeper's verdict. Without `--notarize` that line says UNNOTARIZED.

`SIGN_IDENTITY` picks a certificate by SHA-1 when more than one Developer ID matches. Once Paddle is in `/Applications`, Paddle > Make Paddle the Default Browser… asks macOS to make it the default; copies run from elsewhere (debug builds) refuse.

```bash
xcodegen generate && xcodebuild -project Paddle.xcodeproj -scheme Paddle -configuration Debug -derivedDataPath build/DerivedData.noindex -allowProvisioningUpdates build
```
